## Product findings

The org repository is the correct release base. It has the newer provider-neutral payment-integrity gate, Stripe account/environment checks, payment event ledger, payment audit trail, shared WPistic licensing client, privacy integration, WooCommerce bridge, booking/POS/coreSTORE/FFL adapters, waiver module, corporate membership module, REST controllers, and release automation.

The Guns2Ammo branch contains useful standalone product features that were forward-ported into the org release branch:

- Stripe-backed discount codes with percent/fixed discounts, plan and billing-cycle rules, expiry, global and per-person caps, Stripe promotion-code synchronization, redemption audit records, and an Integrations-page admin panel.
- Payment-gated redemption recording: a discount is only counted after the payment-integrity gate verifies the provider event and amount.
- People email deduplication with a non-destructive audit trail, WP-CLI preview/apply command, and a unique email index migration.
- Account tabs/panels extension filters so add-ons can extend the member account without forking the template.

The Guns2Ammo-only `g2a-suite` client license was not copied into the standalone product. That would couple the public Memberistic plugin to one client contract. The org product keeps its generic WPistic licensing layer; client-specific entitlements belong in Licenseistic/WPistic configuration.

## Release-branch changes

The release branch adds the forward-ported features above and updates the newer payment architecture so:

1. checkout validates a code locally before creating a Stripe session;
2. Stripe receives one server-selected promotion code rather than an unrestricted hosted-page code field;
3. the session metadata identifies the local discount record;
4. activation verifies the discounted amount against the local code record;
5. recurring invoice discounts are verified from the provider invoice's discount total;
6. only accepted payment events create redemption rows and increment usage;
7. duplicate-member cleanup runs before the unique email index is introduced.

## Remaining release gates

Before using this release on a production membership site, run a disposable WordPress upgrade and a Stripe test-mode proof covering:

- clean activation and upgrade from 2.1.1;
- migration 1.13.0 with duplicate and empty member emails;
- discount creation, Stripe synchronization, invalid-code rejection, fixed and percent discounts, caps, expiry, and redemption history;
- successful Checkout completion, webhook retry/deduplication, renewal, failed payment, cancellation, and billing portal;
- member account extension filters and all existing Guns2Ammo adapters;
- privacy export/erase and uninstall policy;
- zip contents, checksum, and a second clean install from the release artifact.

Those are operational gates, not claims made by static source checks.
